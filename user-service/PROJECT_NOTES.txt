================================================================
  PART 1 - WHAT WE DID
================================================================

The project is a Spring Boot microservice (user-service) that will
handle login, registration, password reset, sessions, and admin
user management. Built on Java 17, Spring Boot 4.0.6, PostgreSQL.

We worked through the project in this order:

  1. CLEANUP
     - Renamed the project from "UserSrvice" (typo) to "user-service"
     - Renamed the package from tn.inetum.usersrvice to
       tn.inetum.userservice
     - Renamed the main class from UserSrviceApplication to
       UserServiceApplication

  2. POM.XML (the Maven build file)
     - Added missing dependencies (testcontainers, bouncycastle)
     - Bumped springdoc to a Spring Boot 4 compatible version
     - Pinned the testcontainers version (1.20.4)
     - Removed hypersistence-utils-hibernate-63 because it was
       built for an older Hibernate that Spring Boot 4 no longer
       ships - we'll add the right one when we actually need JSONB.

  3. JWT KEYS
     - Generated an RSA-2048 keypair using openssl:
         private.pem  (used to SIGN tokens - secret)
         public.pem   (used to VERIFY tokens - shareable)
     - Saved them under src/main/resources/keys/
     - Added private.pem to .gitignore so it's never committed.

  4. DATABASE MIGRATIONS (Flyway, see Part 3 below)
     Wrote 6 migration files describing the schema:
       V1 - roles table + seed rows (ADMIN, ACCOUNTANT, VIEWER)
       V2 - users table (with case-insensitive email index)
       V3 - user_roles join table (with granted_by, granted_at)
       V4 - refresh_tokens table (for session rotation)
       V5 - password_reset_tokens + email_verification_tokens
       V6 - audit_logs table, partitioned monthly

  5. ENTITIES (Java classes mirroring the DB tables)
     - User, Role, UserRole + UserRoleId, RefreshToken,
       PasswordResetToken, EmailVerificationToken,
       AuditLog + AuditLogId
     - Three enums: AuthProvider, RoleName, AuditEventType
     - InetAddressConverter to translate between Java's
       InetAddress class and Postgres's "inet" column type.

  6. SECURITY CONFIGURATION
     - PasswordEncoderConfig: Argon2id password hashing
       (slow + memory-hard - hard to brute force)
     - JwtConfig + JwtProperties: loads the RSA keys, exposes
       JwtEncoder (creates tokens) and JwtDecoder (verifies them)
     - SecurityConfig: defines the firewall rules - what's public,
       what needs login, what needs admin role.


================================================================
  PART 2 - PROBLEMS WE HIT AND HOW WE FIXED THEM
================================================================

PROBLEM 1: Test couldn't start - "Failed to determine a suitable
           driver class"
WHY:       application.properties had no database URL. JPA tried
           to connect at startup, no URL -> crash.
FIX:       (Eventually) added a real Postgres URL plus a separate
           src/test/resources/application.properties that disables
           DB-related auto-config in tests.

PROBLEM 2: Build failed - "Could not resolve placeholder MAIL_HOST"
WHY:       application.properties referenced ${MAIL_HOST} but no
           environment variable named MAIL_HOST was set.
FIX:       Gave the placeholders default values, e.g.
             ${MAIL_HOST:smtp.example.com}
           Now if the env var is missing it uses a safe default.

PROBLEM 3: Build failed - "class file has wrong version 61.0,
           should be 52.0"
WHY:       Maven was running on Java 8. Spring Boot 4 needs
           Java 17.
FIX:       Make sure JAVA_HOME points to a JDK 17 install.

PROBLEM 4: Test runner errors with placeholders ${posgres},
           ${admin}
WHY:       Typo - somebody wrote ${posgres} as if it were a
           placeholder, but it was meant to be the literal username.
FIX:       Replaced with proper placeholders that have defaults:
             spring.datasource.username=${POSTGRES_USER:postgres}
             spring.datasource.password=${POSTGRES_PASSWORD:admin}

PROBLEM 5: NoClassDefFoundError: org/hibernate/query/BindableType
WHY:       The dependency hypersistence-utils-hibernate-63 was
           built for Hibernate 6.3, but Spring Boot 4 ships
           Hibernate 7 - they're incompatible.
FIX:       Removed the dependency entirely. We'll add the
           Hibernate-7 compatible version when audit_logs needs
           its JSONB column.

PROBLEM 6: Couldn't run mvnw on Windows from IntelliJ
WHY:       "mvnw" is the Unix script. Windows needs "mvnw.cmd".
FIX:       Either use a terminal, IntelliJ's Maven panel, or
           edit the run configuration to use mvnw.cmd.

PROBLEM 7: "Identity generation isn't supported for composite ids"
WHY:       AuditLog has a composite primary key (id, created_at)
           because the table is partitioned. Hibernate doesn't
           allow IDENTITY generation (where the DB picks the id
           after insert) when the PK is composite.
FIX:       Switched from IDENTITY strategy to SEQUENCE strategy.
           The BIGSERIAL column is backed by the audit_logs_id_seq
           sequence, which Hibernate can read BEFORE inserting.

PROBLEM 8: "A bean with that name has already been defined"
WHY:       I had a class named PasswordEncoder containing a method
           also named passwordEncoder(). Spring registers the class
           as a bean named "passwordEncoder", and the method as a
           bean named "passwordEncoder" too. Same name -> conflict.
FIX:       Renamed the class to PasswordEncoderConfig.


================================================================
  PART 3 - WHAT IS FLYWAY AND WHY WE USE IT
================================================================

WHAT IT IS

Flyway is a database migration tool. You write small numbered
.sql files describing how the schema should change - Flyway
applies them in order and remembers which ones it has run.

Our migrations live in:
   src/main/resources/db/migration/
     V1__create_roles.sql
     V2__create_users.sql
     V3__create_user_roles.sql
     V4__create_refresh_tokens.sql
     V5__create_token_tables.sql
     V6__create_audit_logs.sql

When the app starts, Flyway:
  1. Connects to the database
  2. Checks the flyway_schema_history table
  3. Runs any new files (in version order)
  4. Marks each as applied with a checksum

If you change a migration that's already been applied, Flyway
will refuse to start - this is on purpose, it forces you to
write a NEW migration instead of editing history.


WHY USE FLYWAY INSTEAD OF LETTING HIBERNATE CREATE TABLES?

Hibernate has a setting (ddl-auto=update) that auto-creates
tables from your @Entity classes. It's tempting because it's
zero work. But it has serious problems:

  - It can never DROP or RENAME columns. It only adds.
  - It can't generate Postgres-specific things you need:
      * extensions (pgcrypto)
      * functional indexes (lower(email))
      * partitioning
      * INET column type
      * check constraints
  - It can't seed data. You can't pre-insert your three roles.
  - It's not reproducible - what gets created depends on which
    version of Hibernate is running today.
  - Nobody runs it in production. So you'd have to write
    Flyway migrations EVENTUALLY anyway.

Flyway gives you:
  - A versioned history of every schema change
  - The same schema everywhere (dev, test, staging, prod)
  - Safe rollouts - failed migrations stop the deployment
  - A clear audit trail of who changed what when


================================================================
  PART 4 - WHAT EACH DEPENDENCY IS FOR
================================================================

== Spring Boot starters (the bundles) ==

spring-boot-starter-data-jpa
  The bridge between Java objects and the database. Includes
  Hibernate (the ORM) and Spring Data JPA (which makes
  repositories - one-line database CRUD).

spring-boot-starter-flyway
  Activates Flyway and wires it to run on startup, automatically
  pointing at your datasource.

spring-boot-starter-mail
  For sending emails (verification, password reset).

spring-boot-starter-security
  The core authentication + authorization framework. Provides
  the filter chain, role checks, etc.

spring-boot-starter-security-oauth2-resource-server
  Adds JWT verification on top of starter-security. Lets us say
  "this app trusts JWTs signed by our keypair" and it handles
  the bearer-token parsing automatically.

spring-boot-starter-thymeleaf
  Template engine for the HTML email bodies (verify-email.html,
  reset-password.html). NOT for serving web pages - it's used
  by the mail templates only.

spring-boot-starter-validation
  Bean validation (@NotNull, @Email, @Size, etc.). Used on the
  request DTOs so bad input gets rejected before reaching code.

spring-boot-starter-webmvc
  The HTTP server itself - lets you write @RestController and
  serves them via embedded Tomcat.

spring-boot-devtools
  Live-reload during development. When a class changes, restart
  is fast. Disabled in production builds.


== Database driver + extras ==

postgresql
  The JDBC driver. Lets the app talk to a Postgres database.

flyway-database-postgresql
  Postgres-specific Flyway plugin. Required because Flyway 10+
  separates database support into per-DB modules.


== Hashing / security ==

bcprov-jdk18on  (BouncyCastle)
  A cryptography library. Spring Security's Argon2PasswordEncoder
  uses BouncyCastle under the hood. Without it, password hashing
  fails at runtime.


== Code-gen / boilerplate reducers ==

lombok
  Generates getters, setters, constructors, equals/hashCode at
  compile time. Lets you write tiny entity classes annotated with
  @Getter @Setter @NoArgsConstructor instead of 50-line POJOs.


== API documentation ==

springdoc-openapi-starter-webmvc-ui
  Auto-generates an OpenAPI/Swagger spec from your @RestController
  methods. Serves a Swagger UI at /swagger-ui.html that lets you
  poke at the API from a browser.


== Rate limiting ==

bucket4j-core
  In-memory token bucket library. Used to limit how often someone
  can hit /auth/login or /auth/forgot-password (e.g. 5 logins per
  minute per IP). Prevents brute-force and abuse.


== Test-only dependencies ==

spring-boot-starter-*-test
  Each main starter has a matching test starter. They pull in
  helpers like MockMvc (for testing controllers), test-scoped
  Hibernate setup, etc.

testcontainers + testcontainers/postgresql + testcontainers/junit-jupiter
  Spins up a real Postgres in a Docker container during tests.
  Used by the integration tests so they run against a genuine
  database instead of an in-memory fake. This catches things
  HSQLDB or H2 would miss (like our INET, JSONB, and partitioning).
